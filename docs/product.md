# 产品需求：Games

## 目标

做一个剧情类英语学习游戏，面向公开发布的玩家。玩家通过与 NPC、各种物品的交互（包括口语交互）逐步提升英语听说读写能力，体验生动有趣。

## 用户与核心流程

- **目标用户**：面向公开发布的普通玩家，学习内容为英语；界面支持国际化（多语言），不局限于中文玩家。
- **核心玩法**：剧情驱动，玩家在场景中与 NPC 对话、与物品交互，通过文字和语音两种方式练习英语。
- **语音交互优先级**：口语交互（语音识别/评估）从第一批任务起就要包含，不作为后续迭代补充项。
- **发布形态**：优先做网站（浏览器）版本，无需安装即可玩到核心体验；Steam / 应用商店等其他平台不在当前阶段目标内。

## 游戏系统（2026-09-23 补充）

- **故事与关卡**：游戏以剧情驱动，按"关卡"组织内容，每个关卡有独立的场景、NPC、任务链。第一阶段先做**一条完整的开场关卡闭环**（1 个场景 + 若干 NPC + 一条任务链，走通"剧情引入 → 接任务 → 对话/物品交互推进 → 完成任务 → 获得奖励"整条流程），验证设计是否成立后再决定要不要批量做更多关卡，不在这个阶段就搭"多关卡通用框架"。
- **任务系统**：RPG 式任务日志——玩家可以从 NPC 处接任务，任务有明确的完成条件（比如"用英语跟某个 NPC 完成一次点餐对话"），进行中的任务可追踪进度，完成后发放奖励（积分/经验）。
- **角色与美术**：游戏里的 NPC/角色使用**二维动画角色**（有基础动作，比如待机、说话），美术素材来源是 **AI 生成的占位美术**（不购买现成素材包、不外包定制），成本低、风格可以后续统一替换，不涉及外部付费美术资源。
- **升级与积分**：玩家有积分和等级；积分/等级**会影响可玩内容**——比如达到某个等级才能解锁新关卡、新 NPC，或者对话/任务的难度随等级调整（不是纯展示用的数字）。
- **任务进度**：玩家可以在界面上看到任务的进行状态（未开始/进行中/已完成）和当前等级/积分，作为长期激励的一部分。
- **开场关卡的具体设定**（第一阶段要做的这条闭环）：玩家扮演刚抵达一个英语小镇的旅行者，场景是一家咖啡馆，NPC 是咖啡师。任务链：① 用英语跟咖啡师打招呼、说明自己是新来的 ② 点一杯咖啡和一份点心（练习点单句型） ③ 回答咖啡师的追问（要不要加糖、堂食还是打包）。完成整条任务链后获得经验/积分，等级提升后解锁一点新内容（比如咖啡师多一句新台词，或者解锁镇上第二个 NPC 的入口，具体解锁什么由实现时视复杂度决定，但必须是真实可验证的解锁效果）。这个场景符合"情境先于词汇"的设计原则——点单是最经典也最好上手的英语学习场景。

## 对话理解的阶段性方案（2026-09-24 人类裁决）

- **当前阶段**：NPC 对话继续用规则/短语匹配（免费、不外发数据），但要补齐常见的正确说法（如 "No, thanks"、"I don't want sugar"、latte/tea 等饮品名），并且只在对应任务步骤的语境下推进任务，减少"听不懂正确回答"和"不相关的话误推进"。
- **后续**：是否接入大模型（LLM）做对话理解，等人类看过费用估算与隐私方案（`docs/llm-evaluation.md`）后再决定；在此之前不接入任何外部付费 AI 服务。
- 人类会先亲自试玩开场关卡，试玩反馈可能调整后续优先级。

## 设计原则

参考市面上口碑最好的沉浸式语言/知识学习类游戏（如 Noun Town、Wanderfolk、Influent、Kerbal Space Program、Zoombinis）总结出的共同有效性原理，作为贯穿各功能的产品要求：

- **学习内容即游戏动词**：听说读写的练习必须是玩法本身的一部分（对话、物品交互、任务推进），不能是"玩一段剧情、弹一个选择题"式的外挂测验。
- **失败低成本、即时反馈、不跳出沉浸**：玩家说错/用错英语时，NPC 要给出符合角色的自然反应（听不懂、追问、调侃等），而不是判定"失败"或弹出纠错弹窗打断剧情。
- **长期记忆与后果**：NPC 应记住玩家过往的关键互动/选择，影响后续对话与关系，而不是每次对话都是无状态的孤立事件。
- **情境先于孤立词汇/句型**：先给场景和物品上下文，再引出要学的词汇/句型，不做脱离情境的词卡式灌输。
- **语音是及格线而非加分项**：语音识别与反馈需要在核心流程中真实可用（能听懂玩家说的话并给出针对性反馈），不是占位或简单关键词匹配。

## 明确不做

- 不做多人在线 / 社交联机功能（单机单人体验）。
- 不做内购 / 付费系统（初期不设计变现）。
- 当前阶段不做 Steam / 应用商店发布（网站优先，其他平台留待后续评估）。
- 当前阶段不做"多关卡通用框架"，只做一条关卡的完整闭环，验证设计后再决定是否扩展。
- 角色美术不购买现成素材包、不找人定制原创美术，统一用 AI 生成的占位美术。

## 验收标准

- 能部署为可在浏览器直接访问的网站版本。
- 核心流程可玩通：进入剧情场景 → 与 NPC 对话（文字 + 语音）→ 与物品交互 → 体现听说读写能力的具体训练/反馈机制。
- 语音交互（识别 + 基本评估反馈）在核心流程中可用，不是占位/mock。
- 开场关卡可以完整玩通一遍：进入场景 → 看到有基础动作的二维动画 NPC → 接到任务 → 通过对话/交互推进任务 → 完成任务拿到积分/经验 → 积分/经验实际影响到可玩内容（不是纯数字展示）。
- 玩家能在界面上看到当前任务的进度状态和自己的等级/积分。

## 时间要求

- 无硬性截止日期，按质量推进。
