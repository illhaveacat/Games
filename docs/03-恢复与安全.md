# 恢复与安全

## 为什么不依赖聊天续写

长聊天会压缩或丢失细节。所以每一个会影响后续工作的事实都必须落在 Git、任务文件、测试输出或工件里。新 Coordinator 的第一条指令永远是"把自己当成无状态实例，从仓库重建事实"。

## 中断恢复

Worker 每 10--15 分钟或每个里程碑跑一次 `heartbeat`。协调器定期 `recover`：租约过期的任务标记为 `interrupted`，**分支、提交、日志、工件全部保留**，`assignee` 清空但 `branch` / `baseCommit` / `runId` 留在任务上，下一个 Agent 据此接力，而不是重写。

```bash
orc heartbeat --task AUTH-010 --agent api-01
orc recover --stale-minutes 45
orc show --task AUTH-010          # 恢复入口：分支、基线、工件路径、历史、恢复指令
```

`recover` 还会报告两类滞留：`staleReview`（送审很久没人审）和 `waitingIntegration`（审过了没合并）。这两类不会自动改状态，但会让协调器看见队列为什么不动。

恢复一个 `interrupted` 任务：

```bash
orc show --task AUTH-010          # 取分支与 handoff 路径
git switch agent/auth-010
git log --oneline <baseCommit>..HEAD
cat $AI_CONTROL_ROOT/artifacts/AUTH-010/<runId>/handoff.md
orc claim-task --task AUTH-010 --agent api-02
```

重新 `claim-task` 会把基线重置为当前 HEAD，所以接手者只需要提交自己新增的部分。

## 协调器接管

协调器租约过期后，`recover` 会清空它，下一个协调 Agent 直接 `coordinator-claim` 即可。租约未过期时第二个协调器会被拒绝，不会出现重复派工。

## 门禁分级

- **自动**：写代码、写测试、建分支/PR、部署到临时环境。
- **需审查**：合入集成分支、涉及共享契约的变更。
- **需人工**：生产发布、数据删除/迁移、权限与支付、隐私/合规、外部付费账户、相互矛盾的需求。以上一律 `block`，并把选项/影响/推荐方案/截止时间写进 `docs/decisions.md`。

连续被驳回超过 `maxReworkRounds` 的任务会自动进入 `blocked`。这是防止两个 Agent 之间无限返工烧钱的硬闸。

## 安全约束

- 不要把 `.env`、令牌或生产凭据复制进 worktree；每个环境用自己的受限服务账号，所有 Agent 从最小权限启动。
- 工件里会记录命令输出。`verify` 只截取最后一行且限长 200 字符，但仍要确认你的校验命令不会把密钥打到 stdout。
- 共享控制目录放在仓库外，**不要**放到会被公开推送的位置；里面有分支名、命令输出和决策记录。
- `control/RUNTIME.json` 是本机绝对路径，已被 `control/.gitignore` 忽略，不要提交。
- Agent 不得自行合并自己的 PR，也不得绕过 CI 或审查；`review` 会拒绝自审。
